## 一、原型能力边界

**已实现（可直接体验）**
- 6 个页面全流程闭环：首页 → 分类列表 → 测评介绍 → 答题 → 结果报告 → 海报下载

- openid 免注册：首次打开自动生成 openid 与随机昵称（如「深海鲸鱼」「夜行的猫」）
- 广告位以红色虚线明确标出（信息流 / 激励视频），便于评估变现侵入感

**未实现（原型层面的简化）**
| 项 | 原型做法 | 上线需替换 |
|---|---|---|
| 身份 | 本地随机造 openid | 微信 `wx.login` → 云函数直接取真实 openid |

## 二、免注册账号方案（你的设想，可行）

```
用户首次打开 → wx.login 拿 code → 云函数换取 openid
            → 库里无此 openid？→ 建号（openid 即主键）
            → 昵称 = 动物词库[hash(openid) % N] + 可补随机后缀
            → 无需任何授权弹窗，静默完成
```
- **昵称由 openid 确定性推导**（同一用户每次进入都是同一个昵称，无需额外存储，也不暴露隐私）。
- **重名处理**【待定】：可在昵称后挂 openid 后 4 位（如「深海鲸鱼·a3f9」），避免撞名。
- **不采集手机号、头像、性别**，规避个人信息合规负担；后续若要社交裂变再按需申请授权。

## 五、计分引擎（三种模型，已验证）

开发只需一套引擎，按 `scoringModel` 分支，45 个题库已全量跑通：

| 模型 | 适用 | 选项 score 结构 | 结果判定 |
|---|---|---|---|
| `category` | 「你是哪种 X」，34 个 | `{"cat":"xxx","points":1}` | 各分类累加，取最高；平票按 categories 数组顺序优先 |
| `threshold` | 「XX 指数/等级」，14 个 | `{"points":3}` | 总分落入 bands 区间；bands 已校验连续无空档 |
| `dimension` | 人格轴（MBTI/依恋），2 个 | `{"axis":"EI","pole":"E"}` | 每轴取票数高的一侧，组合后匹配 results.match |

## 六、广告位与变现设计

原型用**红色虚线**标出了 3 处广告位，这是为了让你评估"变现 vs 体验"的平衡：

1. **首页 Banner**（金刚区上方）— 信息流/Banner，曝光位但最伤首屏观感，建议**日活起来后再开**。
2. **结果页「解锁完整解读」** — **激励视频**，收益最高且用户自愿，是主推变现点。
3. **列表底部信息流** — 低侵入补充位。

> **硬约束**：解锁必须用「看激励视频」，**绝不能用「分享给 N 人解锁」**——后者是微信重点打击的诱导分享，会限流甚至封号。原型已按此设计。

## 七、数据模型（上线版）

```
users            _id, openid(UQ), nickname, createdAt, lastActiveAt
tests            testId, title, category, tags, questionCount, resultCount,
                 scoringModel, estMinutes, status           ← 即题库 JSON，可放静态资源
records          _id, openid(IX), testId, resultKey, resultName,
                 answers[], scoreSnapshot, createdAt
```
- `records` 按 `openid` 查，倒序分页；建议**保留最近 100 条**【假设】，超出归档。
- `answers[]` 存原始作答，便于日后改版计分规则重算，也便于做结果分布统计。

## 八、开发方向评估

**推荐方案：微信原生小程序 + 微信云开发（CloudBase）**
理由：openid 由云函数免鉴权直接获取，天然契合你的免注册方案；云数据库/云存储/云函数一体，无需自建服务器、无需备案域名，最省运维成本，最适合轻量化验证。

| 维度 | 建议 |
|---|---|
| 前端 | 原生小程序即可；若后续要铺 H5 投放，再上 Taro / uni-app 一套多端【假设】 |
| 后端 | 云开发三件套；初期不需自建服务 |
| 静态资源 | 题库 JSON 放云存储或打包进小程序包（当前 316 KB，可接受） |
| 工作量 | 【假设】UI 还原 2 周 · 答题与计分引擎 1 周 · 海报 Canvas 1 周 · 历史与列表 1 周 · 广告与合规联调 1 周 ≈ **5–6 周 MVP** |
| MVP 范围建议 | 先上 **10 个**社交钩子最强的（MBTI 待重推则先用职场人设/朋友圈人设/恋爱脑/恋爱依恋/消费人格等），跑通漏斗再补库 |

## 九、合规红线（原型已内置的防护）

- 全站内容按**娱乐/趣味**定位，原型每个介绍页与结果页都带免责声明。
- **禁止**抑郁/焦虑/心理疾病筛查类题目与结论——现有 50 个题库已在生成阶段做违禁词扫描通过。
- 情绪类（心态段位、抗压、孤独感、睡眠、emo、知识焦虑、社恐、讨好、手机依赖）结果页强制标注「娱乐性质，不代表专业心理评估」。
- 解锁用激励视频，不做强制分享；不诱导转发。
- 上线需挂《隐私政策》并在首次进入时确认；未成年人数据需额外保护。

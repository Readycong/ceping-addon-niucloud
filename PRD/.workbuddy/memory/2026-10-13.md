## 50 份 AI 结果评价报告提示词（服务端 system prompt）
- 需求：为每个测评生成一份 AI 结果评价报告提示词，作为服务端系统提示词。
- 交付目录：`提示词/` —— `prompt_001.md`~`prompt_050.md`（50 份自包含，每份约 4.2k 字符）、`prompts.json`（机器可读全集，服务端批量加载）、`_COMMON.md`（第五~七节公共护栏段，2384 字符）、`README.md`（使用说明）。
- 提示词七节结构：①角色 ②本次测评（含**全部可能结果清单**+命中结果基础解说+计分口径）③输入变量 ④任务（含**按类目定制的解读重点**+专属红线）⑤合规红线（8 条）⑥风险兜底（自伤信号→固定危机干预 JSON）⑦输出 JSON Schema。
- 变量规范：统一双花括号 `{{VAR}}`，8 个变量 = USER_NICKNAME / DATE / ANSWER_TRACE / SCORE_DETAIL / RESULT_NAME / RESULT_KEY / BASE_DETAIL / TRAITS。SCORE_DETAIL 按三种计分模型各有一套拼装模板（category 带第二名与分差；threshold 带区间位置；dimension 逐轴给取向与强度）。
- 输出 schema：headline / subline / sections(4 段) / traits / answerEcho / shareLine / disclaimer。核心是 `answerEcho` 必须回扣用户真实作答 ≥2 条，否则报告就是套话。
- 14 个测评带专属红线：#43 禁投资建议、#26/#44 禁健康断言、#8/#19/#31/#33 情绪去病理化、#32/#49 禁"社恐症/成瘾"诊断化、#47 讨好不病理化、#14/#35/#4/#42 禁编造预言。
- 校验（脚本 /tmp/validate_prompts.py + /tmp/simulate_replace.py）：50/50 通过，含变量白名单（禁止非法 `{{}}`）、七节齐全、结果集全覆盖、专属红线与状态标注、风险兜底 JSON 可解析、与 prompts.json 一致；并模拟服务端用真实题库作答替换全部变量 → 0 残留。
- 工程建议：公共段抽离只省维护不省请求 token；服务端须二次校验+禁词扫描；LLM 失败降级到题库静态 detail（AI 报告是增强项）；同一用户同测评结果缓存，避免网赚模型下成本失控。

## 落地 PRD（整合全部资产）
- 交付：`心理测评小程序PRD.md`（v1.0，18 章 + 3 附录）。整合市场定位、50 题库、原型、50 提示词为研发可直接排期的文档。
- 框架：微信原生小程序 + 云开发 CloudBase（云函数免鉴权取 openid，免建登录体系）。
- 关键设计决策（PRD 核心）：
  1. **双层报告**：静态报告（题库 detail，0ms 立即渲染）+ AI 深度报告（异步 2-8s，激励视频解锁）。AI 失败一律降级静态，结果页永不空白。
  2. **服务端复核计分**：客户端只做即时渲染，服务端独立复核一次为准，防篡改。
  3. **题库 572KB 必须走独立分包/CDN**：主包只留 INDEX.json（约 20KB），支持加题修题不发版。
  4. **历史必须服务端持久化**，不能只存 localStorage（换设备/清缓存要能恢复）。
  5. 解锁只走激励视频，严禁分享解锁（微信诱导分享红线）。
- 数据模型：users / records / ai_reports 三集合；云函数 8 个（user.init、test.list、record.submit、report.get、report.generate、poster.qrcode、ad.verify、event.track）；错误码 9 个。
- MVP 10 题（覆盖三种计分模型 + 8 个金刚区）：#5 #9 #11 #2(dimension) #8(threshold) #16 #24 #6 #14 #10。5 个商业版权题不上线。
- 排期：约 5-6 周【假设】，M1 框架 1.5w / M2 核心链路 1.5w / M3 AI 1w / M4 变现 1w / M5 数据合规 1w。
- 北极星指标：周活跃测评完成人次。核心漏斗：曝光→点击→开始→完成→看报告→解锁AI→分享/存海报。
- 变现测算【假设】：eCPM ¥10-30；日活 1 万 × 人均 3 次曝光 → 月收入 ¥0.9-2.7 万，需与 AI 调用成本对冲。

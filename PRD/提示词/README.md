# AI 测评结果评价报告 · 提示词使用说明

> 本目录为 50 个测评各生成一份**服务端系统提示词**，用于调用大模型生成个性化结果评价报告。
> 与 `题库/` 严格一一对应（同一 id、同一计分模型、同一结果集）。

## 一、目录结构

| 文件 | 说明 |
|---|---|
| `prompt_001.md` … `prompt_050.md` | 50 份**自包含**提示词，可直接整份作为 `system` 消息 |
| `prompts.json` | 机器可读全集（含 `systemPrompt` 全文），服务端可批量加载 |
| `_COMMON.md` | 公共护栏段（第五、六、七节），用于 token 与维护优化，见第五节 |
| `README.md` | 本文件 |

## 二、提示词的七节结构（每份都完整自包含）

| 节 | 内容 | 是否随测评变化 |
|---|---|---|
| 一、你的角色 | 解读顾问人设、文风要求 | 否 |
| 二、本次测评 | 名称/类目/计分模型/题量、**全部可能结果清单**、命中结果基础解说、**计分口径** | **是** |
| 三、输入变量 | 8 个变量清单与替换说明 | 否（变量口径随模型微调） |
| 四、你的任务 | 5 条任务要求 + **本类目解读重点** + 专属红线 | **是** |
| 五、合规红线 | 非诊断、禁用表述清单、8 条硬约束 | 否 |
| 六、风险兜底 | 自伤/自杀信号 → 固定危机干预 JSON | 否 |
| 七、输出格式 | 严格 JSON Schema + 结构示意 | 否 |

**第二节注入了全部可能结果**（`key｜名称｜一句话摘要｜关键词`），模型因此能理解本次结果在坐标系中的相对位置——这是生成"你偏X，但Y也不弱"这类精准表述的前提。

**第四节按类目定制解读重点**：情感类讲关系互动、职场类讲协作与能量、玄学类要求轻盈不编造预言、理财类（#43）严禁投资建议、健康类（#26/#44）严禁健康断言、情绪类（#8/#19/#31/#33）去病理化。另有 14 个测评带**专属红线**。

## 三、变量规范

占位符统一为**双花括号** `{{VAR}}`，发送前必须全部替换为实际值：

| 变量 | 说明 |
|---|---|
| `{{USER_NICKNAME}}` | 匿名昵称，仅用于称呼，不得推断身份 |
| `{{DATE}}` | 测评完成日期 |
| `{{ANSWER_TRACE}}` | 作答明细，逐行格式：`[题号] 题干 → 所选选项文本` |
| `{{SCORE_DETAIL}}` | 计分明细，**拼装口径见下（按模型不同）** |
| `{{RESULT_NAME}}` / `{{RESULT_KEY}}` | 命中结果名称与键名 |
| `{{BASE_DETAIL}}` | 题库内该结果的官方基础解说（作为事实依据） |
| `{{TRAITS}}` | 该结果 2–3 个关键词 |

替换后若仍有 `{{...}}` 残留，视为异常，不应发送（已通过 50/50 自动化校验，0 残留）。

### `SCORE_DETAIL` 拼装模板（三种模型各一）

**category（分类累加，34 个）** —— 必须带第二名与分差：
```
各分类得分（由高到低）：卷王 5 分、摸鱼高手 3 分、端水大师 1 分、气氛组 1 分、隐形大佬 0 分；第一名「卷王」(5分)，第二名「摸鱼高手」(3分)，分差 2 分
```

**threshold（分数区间，14 个）** —— 必须带区间位置：
```
总分 23 分，满分 40 分；所属档位「偶尔空落型」(18-25)；距本档下边界 5 分，距上边界 2 分，区间内偏上
```

**dimension（多维轴，2 个）** —— 必须逐轴给取向与强度：
```
关系安全感需求(anxiety)：high（2 vs 2，倾向居中，两种状态会随场合切换）；亲密距离偏好(avoid)：high（3 vs 1，倾向明确）
```

## 四、输出 Schema

```json
{
  "headline": "一句话定调，≤20字",
  "subline": "副标题，≤30字",
  "sections": [
    {"title": "01 核心解读", "content": "100-160字"},
    {"title": "02 你的具体表现", "content": "100-160字"},
    {"title": "03 优势，以及可能的代价", "content": "80-140字"},
    {"title": "04 一条能马上用的建议", "content": "60-120字"}
  ],
  "traits": ["特质1", "特质2", "特质3"],
  "answerEcho": ["你在「题干关键词」这题选了「选项文本」，这个选择透露出……"],
  "shareLine": "≤30字可晒金句，结尾「你呢？」",
  "disclaimer": "本测试为娱乐性质，结果不代表专业心理评估或医学诊断。"
}
```

`answerEcho`（回扣用户真实作答）**是本提示词存在的核心价值**——只围绕结果名写套话的报告，用户一眼就能看出是模板，分享率会塌。

### 调用示例（云函数）

```js
const { systemPrompt } = prompts[String(testId)];
const system = systemPrompt
  .replaceAll('{{USER_NICKNAME}}', nickname)
  .replaceAll('{{DATE}}', date)
  .replaceAll('{{ANSWER_TRACE}}', trace)
  .replaceAll('{{SCORE_DETAIL}}', detail)
  .replaceAll('{{RESULT_NAME}}', r.name)
  .replaceAll('{{RESULT_KEY}}', r.key)
  .replaceAll('{{BASE_DETAIL}}', r.detail)
  .replaceAll('{{TRAITS}}', r.traits.join('、'));

const raw = await llm.chat({
  system,
  user: '请基于以上输入生成结果评价报告，只输出 JSON。',
  temperature: 0.8,      // 解读需要一点文采，但不要飘
  response_format: { type: 'json_object' }
});
```

## 五、工程与成本建议

**1. 公共段抽离（省维护，不省请求 token）**
每份约 4,200 字符，其中第五~七节（2,384 字符）是 50 份完全相同的。建议代码里只维护一份 `_COMMON.md`，运行时拼接 `专属段(一~四) + 公共段(五~七)`——改合规规则时只改一处，不会出现 50 份版本漂移。

**2. 服务端必须做二次校验（不要信模型）**
- JSON 解析失败 → 重试 1 次 → 仍失败则降级
- 字段缺失/超长 → 用题库静态 `detail` 补齐
- **禁词扫描**：对输出跑一遍第五节的禁用表述清单，命中即降级

**3. 降级策略（保证结果页永不空白）**
题库里每个结果已有 80–200 字的静态 `detail`。LLM 超时、报错、被安全策略拦截时，直接渲染静态文案，AI 报告是**增强项不是必需项**。

**4. 成本量级**【假设，待实测】
单次输入约 2,300–2,600 token、输出约 500–700 token。若日活 1 万、人均 1.5 次测评，日调用约 1.5 万次——**这是网赚模型下最主要的成本项**，建议：
- 同一用户同一测评**重复测不重复调**（结果缓存）
- 首屏先渲染静态解读，AI 报告异步生成并写入，避免用户等待

**5. 合规兜底**
第六节的风险兜底是硬性设计：作答文本出现自伤/自杀表述时，模型必须放弃常规解读、只输出危机干预 JSON（含 12355、400-161-9995、010-82951332）。**绝不能**把高危用户导向付费内容。
